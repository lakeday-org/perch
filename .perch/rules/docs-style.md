# Docs style

How perch's own pages are written: README.md, skill.md and every page under
docs/. The rules in perch.yaml are shown this file and judge one section each,
over the part of the page the rule names.

## Headings

A heading names a task or a thing, the way a person would say it out loud: a
noun, or a short verb and noun. CI results, Exit codes, perch scan, List this
branch's CI runs and Show one run's issues are all headings.

These are not:

- A question the page answers, such as What it writes or Why use this.
- A sentence or a fragment of prose, such as Code perch does not read,
  Rewording what perch itself asks, One issue opened up, or Answers that are
  not yes-or-no.
- A clause that describes its subject instead of naming it, such as Read what
  CI found, Check the tests a change needs, The CI runs Perch Cloud has of the
  branch, the issues one run found, or how it scans this repository.

The descriptions in a page's tables name things the same way.

## Sentence length

A sentence is under twenty-five words. One of twenty-five words or more is too
long. So is one that chains three or more full clauses, each with its own verb,
using commas, semicolons and "and". A list of nouns or short phrases inside a
sentence is not a chain of clauses.

## Things are not people

Code, a question, a page or a table is not a person. A sentence that gives one
a mind or a will is wrong: the question's own business, the parser speaks for
it, the rule stopped hedging, the table says, the README knows. A tool doing
what it does is fine: a scan reads a file, a filter narrows a list.

## Empty sentences

A sentence says something. One that announces what is coming instead of saying
it, or points back at something already said without adding to it, is empty.
"Two things, in the order they matter", "There are a few things worth knowing
here", "Before going further, note the following", "It is worth noting that"
and "Each check says which it is" are all empty.
