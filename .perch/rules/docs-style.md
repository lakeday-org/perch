# Docs style

## Headings

- A heading names a task or a thing: CI results, Exit codes, perch scan, Show one run's issues.
- A heading is never a question, such as What it writes or Why use this.
- A heading is never a sentence or a fragment of prose, such as Code perch does not read or Answers that are not yes-or-no.
- A heading never describes its subject with a clause, such as Read what CI found or The CI runs Perch Cloud has of the branch.
- Descriptions in a table follow the same rules.

## Sentence length

- A sentence is under 25 words.
- A sentence has at most two full clauses.
- A list of nouns or short phrases inside a sentence counts as one clause.

## Things are not people

- Code, a question, a page or a table has no mind or will. Wrong: the table says, the README knows, the parser speaks for it, the rule stopped hedging.
- A tool doing its job is fine: a scan reads a file, a filter narrows a list, perch asks a model.

## Empty sentences

- Every sentence states something.
- A sentence never announces what comes next, such as Two things, in the order they matter, or There are a few things worth knowing here.
- A sentence never points back without adding anything, such as It is worth noting that, or Each check says which it is.
